# v0.7 foundation frozen by v0.6.24

This is the architectural handoff from the v0.6 line to v0.7. It does not add
raster nodes or codecs. It fixes the contracts those features must extend.

## Format and capability policy

- Versions 1–3 are legacy documents; version 4 is the ordered scene graph.
- A future document version fails with `[unsupported-capability]` and is never
  interpreted as legacy data.
- Unknown required node kinds fail explicitly. Unknown optional JSON fields at
  document, page, layer, node, style, component, and instance levels survive
  validated edits and migrations.
- v4 extensions implement the existing node validation, traversal, bounds,
  tree/search, flattening, rendering, diff, history, batch, and package seams.
  A feature must either participate in each seam or fail explicitly.

## Resource contract

`resource` is the shared interface for packages and future resource-backed nodes:

- identity is `sha256:<lowercase hex>` over exact bytes;
- embedded and external bytes use the same verification function;
- external paths are nonempty, document-relative, and may not contain parent,
  root, or platform-prefix components;
- reads are local/offline by default; missing data is `[missing-resource]`;
- mismatched bytes are `[hash-mismatch]`;
- encoded resources are limited to 512 MiB before allocation or mutation;
- identical hashes are deduplication keys for a verified cache.

The staged bundle transaction validates the document, revision guard, every path,
and every resource size before mutation. It writes related resources before the
document, restores prior resource bytes if the guarded document commit fails, and
uses the document commit as the single hidden-history entry.

## Bounded-work and error policy

Stable machine-readable codes are included in the human error text:

| Code | Meaning |
|---|---|
| `unsupported-capability` | newer format or required feature is unsupported |
| `limit-exceeded` | bounded input, allocation, recursion, or output limit failed |
| `malformed-resource` | required structure or encoding is invalid |
| `hash-mismatch` | content differs from its declared SHA-256 identity |
| `missing-resource` | an offline resource cannot be found |
| `unsafe-path` | a path can escape its allowed root |

Current reusable limits are: 64 MiB CLI import input, 512 MiB encoded resource or
package archive, 1 GiB expanded package, 64 scene levels, 10,000 search results,
268,435,456 output pixels, and 1 GiB RGBA allocation. Decoders added in v0.7 must
check encoded bytes, decoded dimensions, pixel count, and memory estimate before
allocating.

## Baseline and accepted debt

The v0.6.24 release workflow records release binary sizes and SHA-256 checksums on
Windows x64, Linux x64, Intel macOS, and Apple Silicon. `cargo test --all-targets
--locked` runs conformance, deterministic package round trips, instance visual
regression, transaction faults, and renderer goldens on every release target.
`docs/render-benchmark-v0.6.1.md` remains the representative vector-render timing
and peak-memory method until v0.7 adds a raster-specific benchmark.

Supported formats are v1–v4, with v4 current. Package determinism is enforced by
the package round-trip test and release artifacts are covered by `SHA256SUMS.txt`.
The only accepted debt is feature-specific to v0.7: raster decode/encode limits,
color-space metadata, image-node bounds, and raster renderer timing do not exist
until an image capability exists. They must use the contracts above rather than a
parallel cache, transaction path, or scene graph.
